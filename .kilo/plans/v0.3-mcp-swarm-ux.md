# Copium v0.3 Update Plan

## Overview
Multi-day update focused on MCP (Model Context Protocol) full support, expanded agent capabilities, and improved UX. Target: 5-7 days of implementation.

## 1. MCP (Model Context Protocol) Full Support

### 1.1 MCP Server Registration
- Register Copium as an MCP server exposing all agent tools
- Implement MCP protocol handler (JSON-RPC over stdio/pipe)
- Tools exposed via MCP:
  - `read_file` / `write_file` / `search_files`
  - `run_command` / `run_tests`
  - `git_status` / `git_diff` / `git_commit`
  - `get_diagnostics` / `get_symbols`
  - `apply_edit` / `create_diff`

### 1.2 MCP Client Support
- Allow Copium to connect to external MCP servers
- Configuration: `copium.mcp.servers` array in settings
- Each server: name, command/args, env vars
- Dynamic tool discovery from connected MCP servers
- Merge MCP tools with built-in tools in tool registry

### 1.3 MCP Tool Schema Validation
- Zod schemas for all MCP tool inputs
- Validate before execution (treat LLM tool calls as untrusted)
- Tool input sanitization and path traversal prevention

### 1.4 MCP Settings
- `copium.mcp.enabled` (boolean, default false)
- `copium.mcp.servers` (array of server configs)
- `copium.mcp.timeout` (number, default 30000)

## 2. Inline Completions Provider

### 2.1 Implementation
- `vscode.InlineCompletionItemProvider` registration
- Trigger on keystroke with 150ms debounce
- Ghost text suggestions from configured provider
- Multi-line completions for functions/classes

### 2.2 Configuration
- `copium.inlineCompletions.enabled` (boolean, default true)
- `copium.inlineCompletions.delay` (number, default 150)
- `copium.inlineCompletions.maxTokens` (number, default 256)

## 3. Code Actions / Quick Fixes

### 3.1 CodeActionProvider
- "Fix with Copium" on diagnostics
- "Explain with Copium" on selections
- "Refactor with Copium" on symbols
- Register for `onDidChangeDocument` and `onDidChangeDiagnostics`

### 3.2 Implementation
- Read diagnostic/selection context
- Send to provider with fix/explain/refactor prompt
- Apply returned edit via workspace edit
- Show progress and accept/reject

## 4. Diff Application UI

### 4.1 Diff Review Panel
- Side-by-side diff view in webview
- Accept/Reject buttons per hunk
- Inline diff decorations in editor
- Track accepted/rejected changes

### 4.2 Implementation
- Parse unified diff format
- Render in webview with syntax highlighting
- Apply accepted hunks via `workspace.applyEdit`
- Undo stack for rejected changes

## 5. Self-Correction Loop

### 5.1 Act -> Check -> Retry
- After agent makes changes, automatically run:
  - `npm test` / `pytest` / workspace test command
  - `npm run lint` / workspace linter
  - TypeScript/compilation check
- Parse results and feed back to agent
- Retry up to 3 times on failure
- Stop if changes diverge too far

### 5.2 Configuration
- `copium.selfCorrect.enabled` (boolean, default true)
- `copium.selfCorrect.maxRetries` (number, default 3)
- `copium.selfCorrect.commands` (array of commands to run)

## 6. Workspace Rules (.copium/rules.md)

### 6.1 Rules System
- Read `.copium/rules.md` from workspace root on every request
- Inject rules into system prompt
- Support glob patterns for multi-file rules
- Project-specific conventions, banned patterns, coding standards

### 6.2 Implementation
- File system watcher for `.copium/rules.md`
- Parse markdown sections
- Cache and invalidate on change
- Merge with built-in system prompt

## 7. Permission Tier Enhancements

### 7.1 Granular Permissions
- Tool-level permissions (read-only tools vs write tools)
- Path-based restrictions (allow/deny specific directories)
- Command allowlist/denylist
- Confirmation prompts with detailed action preview

### 7.2 Dry-Run Mode
- `copium.dryRun` setting shows what would happen without executing
- Tool calls return preview instead of executing
- Diff preview for file edits
- Command preview for terminal execution

## 8. Undo/Rollback System

### 8.1 Operation Groups
- Group all agent changes into a single undoable unit
- Track file modifications, deletions, command executions
- "Undo Last Agent Action" command
- Rollback to pre-agent state

### 8.2 Implementation
- Git-based rollback (stash changes before agent runs)
- File backup system for non-git workspaces
- Operation log in `.swarm/operations.jsonl`

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| MCP protocol changes | Pin to stable spec, add version negotiation |
| Performance with many MCP tools | Lazy tool loading, tool caching |
| Complex diff parsing | Use well-tested diff library, limit to unified format |
| Self-correction infinite loops | Hard limit on retries, divergence detection |
| Permission bypass | Server-side validation, path canonicalization |
